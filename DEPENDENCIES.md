# Зависимости GNSS Caster

Основной список хранится внутри `gnss-caster-install.sh`, в блоке создания requirements.txt. Он содержит 30 точных версий с хешами файлов релизов. Установка не обращается к генератору списка и не выбирает новые версии самостоятельно.

## Как обновлять список

1. Пересмотреть нужные версии в блоке requirements.txt и явные версии в `tools/build_dependency_lock.py`.
2. Запустить `python tools/build_dependency_lock.py` в окружении разработчика с pip и доступом к PyPI. Скрипт сохраняет существующие точные версии и добавляет недостающие косвенные зависимости; конфликт требований завершает работу до записи результата.
3. Проверить изменения установщика и `tests/dependency_metadata.json`, включая новые косвенные зависимости.
4. Выполнить `python -m unittest discover -s tests -v`, затем проверку на Linux и целевом оборудовании.

Генератор использует библиотеку packaging, поставляемую с pip в окружении разработчика. Этот способ не является частью установки на Raspberry Pi.

## Что уже проверено

В `validation/dependencies` сохранены копия проверенного списка и отчёты pip dry-run для ARM64 с Python 3.11 и 3.14. Все 30 пакетов доступны как wheels для указанных вариантов, хеши скачанных файлов совпали. Установка пакетов и исполнение ARM-кода не выполнялись. `--no-deps` в пробных командах нужен для выбора ARM-файлов с Windows; зависимости выбранных wheels дополнительно проверены по метаданным для Linux.

Пример повторной проверки после извлечения актуального списка в validation/dependencies/requirements.txt:

```text
python -m pip install --dry-run --ignore-installed --no-deps --require-hashes --only-binary=:all: --platform manylinux_2_28_aarch64 --platform manylinux_2_17_aarch64 --platform manylinux2014_aarch64 --python-version 3.11 --report validation/dependencies/aarch64-python311.json -r validation/dependencies/requirements.txt
```

## Границы проверки

- Метаданные проверяются для CPython 3.11–3.14 и Linux aarch64, armv7l, x86_64. Это не тест запуска приложения.
- На ARM32 может потребоваться компиляция. Компилятор, apt-пакеты и зависимости изолированной сборки исходников пока не закреплены.
- Для изменения или исправления уязвимости нужно выпустить обновлённый список; автоматического перехода на новую версию нет.
- `pip check` проверяет совместимость установленных зависимостей, но не поведение приложения и не безопасность кода.
- Хеши защищают от подмены выбранных файлов после формирования списка. Они не доказывают безопасность пакетов.

Источники: [метаданные PyPI](https://docs.pypi.org/api/json/), [режим проверки хешей pip](https://pip.pypa.io/en/stable/topics/secure-installs/).
# Веб-зависимости 3.1.0

React, Material UI и инструменты сборки закреплены в `frontend/pnpm-lock.yaml`. Они нужны только на машине разработчика. На Raspberry Pi поставляются уже собранные файлы внутри установщика; Python-зависимости и способ их установки не изменены. Порядок сборки и проверок: `frontend/README.md`.
